# Demo video brief (from the owner, 24 Nov)

These rules come first. Every scene, every line of voiceover and every transition has to pass them.

## What it is

- A **product unveiling**, made as a **motion video**. Done right the first time: no rough drafts shown, no "we'll fix it later".
- Sharp, deliberate, premium. **No slop**: no AI-sounding lines, no AI-looking visuals, no generic stock effects.
- **Smooth, really good transitions.** Every cut is designed: one shot moves into the next.

## What it must explain

- **How Greenlight works with Kane CLI and Claude Code.** That is the hackathon requirement, and the heart of the video.
- The whole process, clearly:
  1. checking the app,
  2. a claim failing, and what Kane saw,
  3. Greenlight bringing up the fix,
  4. the user running it in Claude Code,
  5. first time: how they install it,
  6. Claude Code fixing it and Kane checking again until it passes.
- Shown in a **Claude Code terminal** on screen, so the loop is seen, not just described.

## What it must not have

- **No technical commands or jargon in the voiceover or as on-screen focus.** No flags, endpoints, job ids, tokens or code walkthroughs. Plain words a judge understands on first watch.
- Nothing confusing. If a line needs explaining, cut it.
- No AI-slop phrases: "introducing", "seamlessly", "game-changer", "revolutionise", "in today's world", "imagine a world", "supercharge", "unlock", "effortless".
- No AI-looking visuals: no floating particles, lens flares, generic glowing orbs, fake holograms, stock "tech" backgrounds.

## Sync

- **The voiceover matches the clips.** Each line is written for its shot and timed to it; the picture shows what the voice says, when it says it.
